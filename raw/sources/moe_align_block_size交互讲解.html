vLLM moe_align_block_size 交互式详解

基础原理 · 专家并行（EP / expert_map）· 数据并行（DP / batched 变体）—— 所有图示均可手动步进控制

一句话作用：把路由器输出的散乱 topk_ids 整理成「按专家连续存放、每个专家的槽位数补齐到 block_size 整数倍」的布局，让 grouped GEMM 的每个线程块只查一次专家号、整块复用同一个权重矩阵。

场景一：基础版 moe_align_block_size

示例：8 个 token、top-2、4 个专家、block_size = 4。点击「下一步 / 上一步」逐帧查看，也可用「播放」自动演示（速度可选）。

场景二：专家并行（EP）时有什么不同

EP 把 N 个专家切到多张卡上。此时 num_experts 传全局专家数，并传入 expert_map（全局专家号 → 本卡局部号，不在本卡的记为 -1）。函数有两种工作模式：

  • 默认模式（ignore_invalid_experts=False）：先对全部全局专家做计数、排序、补齐（所有 token 都参与对齐），返回前把 expert_ids 经 expert_map 映射——非本卡专家的块被标成 -1，MoE GEMM kernel 遇到 -1 直接跳过该块。
  • 过滤模式（ignore_invalid_experts=True）：计数阶段就直接忽略非本卡专家，它们的 token 不参与对齐，缓冲更小，expert_ids 里也不会出现 -1。

示例：8 个全局专家、EP=2（Rank 0 持有 E0–E3，Rank 1 持有 E4–E7）、8 个 token、top-2、block_size = 4。

场景三：数据并行（DP）—— batched_moe_align_block_size

这个变体不是凭空多出来的，它是为 DP（数据并行）+ EP（专家并行） 部署（典型代表：DeepSeek 系列）量身定做的。要理解它，先得看清楚 MoE 层每一步的完整流水线：

  1. 每张 DP 卡各拿一批 token，各自跑路由器，确定每个 token 该去哪些专家；
  2. All-to-All Dispatch：通过网络把每个 token 发送到「持有它目标专家的那张卡」；
  3. 每张卡只对自己持有的专家做 GEMM 计算；
  4. All-to-All Combine：把算完的结果发回原卡，按路由权重加权求和。

麻烦出在第 ② → ③ 步之间：每一步、每个专家能收到多少 token 完全是随机的。如果按实际数量现分内存，张量形状步步都变——CUDA Graph 没法捕获（它要求所有张量形状固定），通信和计算 kernel 也没法做定长优化。vLLM 的对策：Dispatch 直接把 token 写进一块形状恒定的缓冲 (E × max_tokens_per_batch, K)——每个专家固定占一排位置，来几个写几个，空着就空着，再配一个 expert_num_tokens 数组记录每排实际有几个有效。

这时 batched_moe_align_block_size 的活就很简单了：token 已经被通信层按专家分好段，它不用像基础版那样先做排序，只负责「打包」——把每排的有效 token 数向上凑成 block_size 的整数倍，生成和基础版语义完全相同的三个输出。下面用一个停车场类比一步步走：每个专家有一排固定的 8 个车位，token 是车，GEMM 按 4 辆一卡车拉走。

示例：5 个专家（E = 5）、每排 8 个车位（max_tokens_per_batch = 8）、block_size = 4、本轮实停 expert_num_tokens = [2, 3, 0, 6, 8]。

附：输入输出与 kernel 消费方式

参数 / 返回含义
topk_ids[num_tokens, top_k]，每个 token 选中的专家编号（EP 时为全局专家号）
block_sizeGEMM 块长，即 kernel 的 BLOCK_M（通常 16/32/64）
num_experts专家总数；EP 场景必须是全局专家数
expert_map全局 → 本卡局部专家号映射；不在本卡的为 -1
ignore_invalid_expertsTrue：计数阶段直接忽略非本卡专家；False：全部对齐后把非本卡块标 -1
sorted_token_ids（出）对齐后的槽位下标；槽位 i ↔ 激活第 i//top_k 行；补位填 numel（越界值，被 mask）
expert_ids（出）第 i 个块用哪个专家；-1 表示整块跳过
num_tokens_post_padded（出）补齐后的总槽位数，决定 GEMM grid 大小
# fused_moe_kernel 中（简化）
pid_m = tl.program_id(0)
e     = tl.load(expert_ids_ptr + pid_m)              # 整块只查一次专家号；-1 则整块跳过
offs  = tl.load(sorted_token_ids_ptr + pid_m*BLOCK_M + arange(BLOCK_M))
mask  = offs < numel                                  # PAD 槽位被屏蔽，结果丢弃
a_ptrs = a_ptr + (offs // top_k) * stride_am         # 槽位号 → 激活行号
b_ptrs = b_ptr + e * stride_be                       # 整块复用权重 W_e
  • 实现：三段式（原子加计数 → 带 pad 前缀和 → scatter 写回），输出缓冲按上界 numel + num_experts×(block_size−1) 预分配。
  • 开销：只处理 num_tokens×top_k 个 int32 下标，相对后续 GEMM 可忽略。
  • 注意：当前 main 分支官方 docstring 中 batched 示例的 expert_ids 有个小笔误（写作 [0,1,3,3,4,5,5]），按 golden 测试的正确结果是 [0,1,3,3,4,4]——本页面按正确行为绘制。
