# 华为昇腾（Ascend）NPU 硬件架构调研笔记

## 1. Da Vinci 架构：AI Core 的组成

昇腾 AI 处理器的计算核心是 **AI Core**，属于 DSA（Domain Specific Architecture）。每个 AI Core 包含三种计算单元，形成**三条独立执行流水线**，由控制单元统一调度（来源：hiascend 官方文档《AI Core架构》）：

| 单元 | 职责 | 算力量级 |
|---|---|---|
| **Cube Unit**（矩阵计算单元） | 矩阵乘加。一次执行完成 FP16 16×16 × 16×16（=4096 MAC），或 INT8 16×32 × 32×16（=8192 MAC）；A 矩阵来自 L0A、B 来自 L0B、结果写入 L0C | 占整芯片算力 ~99%，是 FLOPS 的主要来源 |
| **Vector Unit**（向量计算单元） | 向量/逐元素运算：activation、LayerNorm、Softmax、reduce、gather 等；算力低于 Cube 但更灵活（支持倒数、开方等）。源数据和结果必须位于 Unified Buffer，要求 32B 对齐 | 约 2048-bit 宽向量/周期（初代），910B 约 9 TFLOPS FP32 |
| **Scalar Unit**（标量计算单元） | 标量运算 + 流程控制：循环、分支、地址计算、为 Cube/Vector 指令计算参数，相当于一个小 CPU | — |

**重要代际变化（910B 起）**：一个物理 AI Core 被拆分为 **1 个 AIC（AI Cube core）+ 2 个 AIV（AI Vector core）**（比例因型号而异），AIC/AIV 各自含独立 Scalar Unit，编程模型上向量核数量翻倍（来源：arXiv 2505.15112）。

### 内存层级（程序员可见的 scratchpad 体系）

不同于 GPU 的 cache 主导，昇腾是**显式管理的 buffer 层级**（容量为初代 910 的典型值，新型号可用 `get_soc_spec` 查询）：

| 层级 | 容量（初代 Da Vinci） | 用途 |
|---|---|---|
| GM（Global Memory，即 HBM/DDR） | 32–128 GB | 片外主存 |
| L2 Cache | MB 级（910B 实测 192 MB） | 芯片级共享缓存 |
| **L1 Buffer** | 1 MB | AI Core 内最大的中转区；Img2Col 等格式转换要求源数据在 L1 |
| **L0A / L0B Buffer** | 各 64 KB | Cube 指令的输入（A/B 矩阵） |
| **L0C Buffer** | 256 KB | Cube 的输出/累加器（FP32 累加） |
| **Unified Buffer (UB)** | 256 KB | Vector/Scalar 计算的输入输出 |
| Scalar Buffer + GPR/SPR | — | 标量计算、配置寄存器 |

### MTE（Memory Transfer Engine）

数据搬运由专用 DMA 引擎完成，与计算并行（类比 NVIDIA 的 `cp.async`/TMA）：

- **MTE2**：GM → L1 / L0A / L0B / UB（数据加载）
- **MTE1**：L1 → L0A / L0B / UB（片内搬运 + 格式转换：padding、transpose、Img2Col）
- **MTE3**：UB → GM（结果写回）
- **BIU**：AI Core 与总线交互的接口

控制上采用**多队列乱序执行**：指令顺序译码后分派到 S/V/M/MTE1/MTE2/MTE3 六个队列，队列内顺序、队列间在满足依赖前提下并行，用 `set_flag/wait_flag` 和 Barrier 做跨队列同步——这是算子流水线编排（double buffering 等）的硬件基础。

## 2. 产品系列规格对比

| 规格 | Ascend 310P（推理） | Ascend 910（2019） | Ascend 910B（2023–24） | Ascend 910C（2025） |
|---|---|---|---|---|
| 定位 | 边缘/DC 推理 | 训练 | 训练/推理 | 训练/推理 |
| FP16 | 70 TFLOPS | 256–320 TFLOPS | ~320 TFLOPS（实测 Cube 峰值 294.9） | **~800 TFLOPS**（BF16 780） |
| INT8 | 140 TOPS | 512–640 TOPS | ~640 TOPS | 1600 TOPS |
| FP8 | ❌ | ❌ | ❌ | ❌（950 起支持） |
| HBM | 无（LPDDR4X 24 GB @ 204.8 GB/s） | 32 GB HBM2 @ ~1.2 TB/s | 64 GB HBM2e @ ~1.6 TB/s | **128 GB HBM2e（8 堆叠）@ 3.2 TB/s** |
| AI Core 数 | 8–10 Da Vinci 核 | 32 | 20 AIC + 40 AIV（实测） | 每 die 25 AIC + 50 AIV，双 die |
| 片间互联 | PCIe 4.0 | HCCS | HCCS 392 GB/s 总带宽（P2P，单对 56 GB/s） | UB 2,800 Gb/s scale-up + 400 Gb/s RDMA |
| 制程/功耗 | 整卡 72 W | 7nm，310 W | SMIC 7nm（N+1/N+2），~400 W | SMIC 7nm，~600 W |

**910B vs 910C 的关键区别**：910C 并非新架构，而是**两颗 910B 级 die 封装在同一有机基板上**（dual-die, Da Vinci v2），因此算力/HBM 大致翻倍（800 TFLOPS、128 GB、3.2 TB/s），代价是 die 间互联带宽远低于 NVIDIA 的先进封装方案。⚠️ 未确认：SemiAnalysis 拆解称部分 910C die 来源涉及管制前囤积的 TSMC 7nm 产能。910B 内部还有 B1–B4 变体（算力/显存配置不同，早期 B1 为 32 GB）。

## 3. 与 NVIDIA GPU 的概念对照

| 昇腾 | NVIDIA | 对应是否成立 |
|---|---|---|
| AI Core | SM | ✅ 基本成立：独立调度、自带存储的最小计算单元。差异：AI Core 内是异构三单元而非同构 lane |
| Cube Unit | Tensor Core | ✅ 成立：都是矩阵乘加引擎。Cube 一条指令完成整个 16×16×16，粒度比 Tensor Core 的 MMA 指令更粗 |
| Vector Unit | CUDA Core | ⚠️ 部分成立：功能对应（element-wise、激活等），但 Vector Unit 是**宽 SIMD**（2048-bit 向量），不是 SIMT 线程 |
| UB / L1 / L0 | Shared Memory / Register File | ✅ UB ≈ Shared Memory（软件管理的 scratchpad）；L0A/L0B/L0C 更接近 Tensor Core 的 operand register 的显式化 |
| GM | Global Memory (HBM) | ✅ 成立 |
| MTE | cp.async / TMA / DMA | ✅ 成立：异步搬运引擎，用于计算-搬运重叠（double buffering） |
| HCCS / UB | NVLink / NVSwitch | ⚠️ HCCS 是 P2P 拓扑（无 NVSwitch 式交换芯片），8 卡总带宽 392 GB/s 看似接近 A800 的 400 GB/s NVLink，但单对 GPU 间仅 56 GB/s |

**SIMD vs SIMT 本质差异**：NVIDIA GPU 以 warp（32 线程）为单位做 SIMT，每线程有独立寄存器和（逻辑上的）控制流；昇腾 Vector Unit 是显式 SIMD——一条向量指令对 UB 中 256B 对齐的整块数据流水处理，分支控制由 Scalar Unit 负责。结果是：昇腾在规则、密集的张量负载上面积/能效更优，但对不规则、离散访存（gather/scatter、稀疏）的灵活性弱于 SIMT。**值得注意的是，华为官方宣布 Ascend 950 起将采用"SIMD + SIMT 结合"的创新设计**（访存粒度从 512B 细化到 128B），等于承认纯 SIMD 的局限并向 GPU 编程模型靠拢。

## 4. 2024–2026 最新动态

- **910C 量产**：2025 Q1 起规模出货；2025 年 3 月华为正式发布 **Atlas 900 A3 SuperPoD**（最多 384 颗 910C），云服务形态即 **CloudMatrix 384**：384 NPU + 192 Kunpeng CPU，UB 全互联 all-to-all，~300 PFLOPS BF16、48+ TB HBM，功耗 ~559 kW。SemiAnalysis 评价：芯片落后 NVIDIA 一代，但 scale-up 系统设计领先（对比 GB200 NVL72：1.7× 算力、3.6× 显存、~4× 功耗）。已部署 300+ 套（来源：Huawei Connect 2025 官方 keynote）。
- **官方 roadmap（Huawei Connect 2025，徐直军 keynote）**：
  - **Ascend 950PR**（2026 Q1，prefill/推荐优化，自研低成本 HBM **HiBL 1.0**，128 GB ⚠️ 容量数字来自 TechInsights 非 keynote）与 **950DT**（2026 Q4，decode/训练优化，**HiZQ 2.0** HBM：144 GB、4 TB/s；互联 2 TB/s = 910C 的 2.5×）。950 系列：**1 PFLOPS FP8 / 2 PFLOPS FP4**，新增 FP8、MXFP8、MXFP4 及华为私有 **HiF8** 格式。
  - **Ascend 960**（2027 Q4）：2 PFLOPS FP8 / 4 PFLOPS FP4，新增 **HiF4**，显存容量/带宽/互联端口翻倍（288 GB、9.6 TB/s、2.2 TB/s）。
  - **Ascend 970**（2028 Q4）：4 PFLOPS FP8 / 8 PFLOPS FP4，互联 4 TB/s。
  - 950 起采用自研 HBM + SIMD/SIMT 混合架构。
- **超节点路线图**：Atlas 950 SuperPoD（8192 × 950DT，8 EFLOPS FP8，16 PB/s 互联，2026 Q4）；Atlas 960 SuperPoD（15,488 NPU，30 EFLOPS FP8，2027 Q7）；SuperCluster 级别规划到 100 万 NPU（2 ZFLOPS FP8）。互联协议 **UnifiedBus (UB / 灵衢) 2.0** 技术规范已开放。
- **2026 年新动态**：华为在 Huawei Connect 2026 将 960 系列提前，发布 960PR（prefill 向，8 PFLOPS FP4、192 GB、2.4 TB/s）与基于近封装光学（Hi-ONE NPO）的 960 超节点（4096 卡，8 EFLOPS FP8），并提出 "Peerium" 系统架构（来源：MLQ/Tom's Hardware，⚠️ 细节待官方文档确认）。
- **软件生态**：CANN 编译器与虚拟指令集开放接口、其余全面开源（承诺 2025-12-31 前，基于 910B/910C 设计），Mind 系列工具链与 openPangu 模型同步开源。
